## Overview

The docs/apps/web directory contains the root-level Jest configuration files used to run the web application's tests and a focused set of subdirectories that group UI components and library/test assets. At the root, jest.config.js builds and exports a Jest configuration tailored for a Next application, while jest.setup.js provides the test environment setup specific to the web app. These two files together define how tests are discovered, transformed, and initialized for the web application codebase.

Beneath the root are two subdirectories: components/ and lib/. The components/ subdirectory holds React UI component modules (Dialer, LiveCallIntelligence, MessageList) and their accompanying unit tests; the Dialer component imports useState, and LiveCallIntelligence imports useState, useEffect, and useMemo as noted, indicating component-level reactive logic. The lib/ directory is dedicated to automated tests related to storage functionality used by the web app and currently does not contain runtime source files at its root; instead it groups storage-specific validation artifacts under a test-focused structure. Together, the root-level Jest configuration and the subdirectories provide a unified testing surface for UI components and storage tests, enabling consistent test execution and environment setup for the web application portion of the repository.


### File Organization

Files are organized by feature and purpose: root-level files define test configuration and setup for the web app (jest.config.js and jest.setup.js), the components/ subdirectory groups React UI component modules and their unit tests, and the lib/ subdirectory groups library-related test artifacts for storage. This keeps test configuration centralized while grouping implementation and storage tests by area of responsibility.
